# Wayfire computer use

Use `target/release/wayfire-computer-use` relative to this skill directory. Build once with `./build.sh` if the executable is absent. The CLI uses no Python, GStreamer, external C helper, model API or API key. Read [usage](references/usage.md) for system libraries, build instructions and capability limits.

For an MCP host, use the optional [stdio adapter](references/mcp.md). It returns a PNG in each observation or action result and manages the action envelope. The same output-selection, observation and stop rules apply.

1. Run `doctor`. Inspect outputs, protocol versions, D-Bus service ownership and PipeWire socket access. This command does not create input devices or capture sessions. Do not change permissions or switch backends to evade access restrictions.
2. Run `start`, optionally with `--output NAME`. A sole output is selected automatically. With multiple outputs, ask which output to use and require `--output NAME`; never guess. The selected output must have scale 1 and normal orientation. Multiple-output binding requires virtual-pointer v2 and unambiguous stream geometry; unsupported or ambiguous configurations fail explicitly.
3. Portal source selection can require interaction. Only with explicit user authorization, add `--auto-select-output` to permit one native virtual-pointer click on a newly detected slurp monitor selector. This bootstrap is pointer-only, submits a start notification first, and never retries automatically. Process detection cannot prove an active input grab; stop on ambiguity or disappearance.
4. Use `toplevel list` when window discovery is needed and `toplevel focus --id ID --pid PID` for an identified target (omit --pid only when unavailable). Read [window management](references/usage.md#window-management) for IPC requirements and stale-observation handling. Resolve ambiguous window identity before requesting focus. Actually view the returned PNG with the host image viewer before ordinary input. A path alone is not an observation. Identify the target and current focus. Input shares the user's cursor and keyboard focus; serialize control and stop if unexpected changes invalidate the target.
5. Send one action envelope to `act` on stdin, using the current session_id/observation_id and a new request_id. View every resulting screenshot before continuing. Supported actions are screenshot, wait, move, click, double_click, drag, scroll, keypress and type. See [actions](references/actions.md).
6. Treat action_executed on an error as possible partial execution. Do not automatically replay side effects. Identical request IDs deduplicate only within the current session; changed content with the same ID fails. Layout changes invalidate old coordinates. Stop and restart to establish a new mapping after failures.
7. Always `stop` at completion, cancellation or failure. It bypasses the action queue and waits for input/capture/Portal cleanup and the end-notification attempt. Inspect the errors array. Repeated stop returns the saved completion result. `release_all` is a recovery management command, not a standard action.

The same Rust executable runs a supervised input-worker process; no separate helper artifact is needed. A failed start notification prevents ordinary input. End notifications follow device cleanup and control-lock release. Notifications do not prove the user saw them. Killing the entire process group or losing the desktop bus can prevent an end notification.

Chinese, ASCII and BMP symbols use temporary keymaps with experimental settling delays. In native key mode, text containing any non-BMP code point is rejected in full before input with UNSUPPORTED_NON_BMP_TEXT: Chromium native key input corrupted a tested emoji even though GTK accepted it. This also excludes supplementary CJK characters and many emoji; do not split or silently omit them. Do not infer universal IME/toolkit support. For explicitly authorized clipboard replacement, use the clipboard mode in [actions](references/actions.md). The complete historical reliability matrix is not claimed as passed. See [tested scope](references/compatibility.md) and [troubleshooting](references/troubleshooting.md). This skill does not register a native computer tool.

For a single caller that has inspected the current observation, `act --latest` accepts a bare action on stdin, e.g. `{"type":"wait","duration_ms":500}`. It reads the current IDs and generates a fresh request ID. Use the explicit envelope for concurrent callers or retryable requests and replay the identical envelope after a lost reply. After an idle shutdown, start the selected output again, list and focus the intended window, and inspect a fresh screenshot before input.

Use `toplevel wait --app-id ID [--focused] [--timeout SECONDS]` to wait for a mapped window through Wayfire IPC. For visual stability use `{"type":"wait_stable","frames":3}`; a static source that stops producing frames can time out. Doctor and active status expose logind `locked_hint` (null when unavailable). An observed lock stops control. A false or unavailable hint still requires visual inspection.
