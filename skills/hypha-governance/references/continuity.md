# Continuity Examples

## Missing Context During Work

Code shows a local process, but not whether hosted processing is acceptable. Search `hosting,offline,cloud,customer`, inspect task links, and read candidate bodies before asking.

Reuse a saved isolated-network restriction within its customer/condition, without reconfirmation. Internet access does not authorize data transfer; another customer's policy does not apply automatically. Current corrections prevail. If project files and bounded Hypha search leave a gap, ask only about that decision while continuing independent work; do not search archives or invent history.

## What To Capture

| Information | Action |
| --- | --- |
| README supplies the build command | Cite it; no knowledge duplicate. |
| User explains why an isolated customer rejected hosted processing | Save scoped rationale, rejected option, and review condition; link implementation. |
| User explicitly asks to remember Orion's deployment choice | Save exact words with scope/origin; no second confirmation. |
| Agent suspects every customer needs isolation | Uncertain inference/draft, not universal user agreement. |
| A test used a temporary port | Keep in execution context unless recovery depends on it. |

Knowledge preserves missing answers and conditions with appropriate attribution, not credentials or transcripts.

## Multiple Plans, One Goal

Task 0001 delivers CSV/JSON ingestion and recovery. Plan A verifies CSV; Plan B handles the rest. Record the milestone and keep 0001 open: plan replacement creates neither a new root nor fresh verification.

If the customer replaces JSON with XML, preserve the task identity and CSV evidence; cancel JSON explicitly, retain XML/recovery as unverified acceptance, and record why. An independently schedulable analytics report may be a linked child or another authorized task; a parser helper normally remains an acceptance detail. Preserve real prerequisites and blocked work when reorganizing.

## Material Change Record

Update current Acceptance and add dated `Change History`, for example:

> On the actual change date, the user replaced JSON with XML because the customer's export format changed. CSV evidence remains valid; JSON is cancelled; XML and recovery remain open. JSON-specific decisions no longer govern XML; link any replacement knowledge.

This is illustrative prose, not a mandatory form. Preserve the reason/authority and every unfinished item's destination; cancel no unrelated scope. Current task content should explain remaining work without old plans or chat. Replace stale handoff scope such as "implement JSON" with a current-task pointer, retaining only missing recovery details.

## Handoff Recovery

Follow SKILL.md's prepare/review/finalize sequence; preparation alone is not a completed handoff. Finalization neither completes tasks nor ends active work.

Without a resume topic, the latest completed handoff is preferred: read its current task/Next Step, knowledge, and recovery references. Changed hashes/statuses require rereading current files, not restoring old versions. An explicit topic uses topic retrieval with handoff as supplemental context. Unfinished preparation warns that the prior handoff was unconfirmed.
